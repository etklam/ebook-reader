## 檢查結果

- `pnpm lint`、`pnpm typecheck`、`pnpm test` 與 `pnpm --filter web build` 通過。單元測試：server 100、web 28、M0 10，共 138 項。Web 測試入口改為收集整個 `src/**/*.test.ts`，避免漏跑新增案例。
- PostgreSQL 完整回歸共 95 項，首次 94 通過；唯一失敗為安全測試硬比對 `Cache-Control: no-store`，而新回應是更明確的 `private, no-store`。斷言改為驗證不可快取指令後，相關安全／權限回歸 **12/12** 通過。其餘案例沒有失敗。
- 匯入最終補強後另重跑人工 review 與既有覆蓋／冪等／回復回歸，**8/8** 通過；包含舊呼叫未提供 analysis token 時，維持升級前持久化冪等 hash 的檢查。
- 瀏覽器共有 **35 個不同案例具最終通過紀錄**。首次完整跑 33 項，32 通過；舊書籤情境未關閉新備註步驟，且沿用上一情境的閱讀位置。測試改為明確回章首、儲存備註後繼續，會員整檔 **4/4** 通過。新增匯入與朗讀最終相關檔案 **4/4** 通過，包含新增的兩個匯入 UI 案例。
- `pnpm db:verify` 全部通過；無新增套件、無新增 migration。
- 390px 與 1200／1280px 的書庫篩選、目錄、書籤、匯入畫面已檢視；未見文件橫向溢出。沿用既有 tokens、原生控制項、44px 觸控目標及 bottom sheet。
- 最後一次介面機械掃描僅回報 app.css 原有的五項字級 advisory，與先前 audit 所列相同；本次新增控制項未引入這些字級，未將 advisory 當成已驗證的缺陷或擴大修改範圍。
- 工作區原有 App 路由分拆、ExportPanel 錯誤處理及樣式變更已保留；本次未提交或推送 Git。

## 效能證據與限制

完整方法、原始 JSON、重跑指令與前後數字見 [效能比較](../../perf/reader-improvements-2026-10-15.md)。

- 長章 90 次定位：段落幾何查詢 400,070→1,118，定位 p95 4.20→0.40ms；此情境幀間距沒有改善，兩版皆未出現長任務，不宣稱真機掉幀已解決。
- 命中密集的 500 章搜尋：正文讀取 500→56 章；無命中仍讀 500 章，本次耗時沒有改善。搜尋 I/O 基準使用真檔案與固定 metadata 替身，不含 PostgreSQL／網路／生產壓測。
- 真實本機 API 的預載樣本在切章時省一次正文請求，但冷／暖操作時間約 271／273ms，無可辨識改善；只有各一筆，不是 p95。
- 實體 iOS Safari／Android Chrome、系統語音、背景／鎖屏播放及原 L3 清單**尚未執行**。ER-008 最後一項真機語音驗收保留未勾，其程式與自動驗證已完成。
- 另外發現既有進度同步的並行／過期回呼風險，已記於待決的 ER-009；這不是本批新增行為，也未當成已修復。

## 本機重跑

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm --filter web build
pnpm --filter server test:e2e
pnpm --filter web test:browser
pnpm db:verify
```

資料庫整合需要本機 PostgreSQL；瀏覽器完整套件需要 API、worker 與 web。效能腳本另見量測文件，真機驗證仍依 L3 清單記錄裝置與結果。
