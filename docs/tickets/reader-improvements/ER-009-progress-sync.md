# ER-009｜進度同步狀態與跨裝置衝突處理

- 優先級：P2
- 工作量：中
- 類型：HITL
- 狀態：needs-triage

## 要做的事

身為跨裝置閱讀的會員，我希望知道目前位置是否已同步，並在兩台裝置產生衝突時理解將採用哪一個位置。

目前進度有本機保存及樂觀並發控制；衝突時採用伺服器位置，並顯示短暫提示。補上「已同步／待同步／僅存本機／重試中」狀態，並確認是否要把既有自動採用伺服器的位置政策改成由讀者選擇。

## 實作前待確認的決策

- 保留既有「伺服器位置優先」，只改善提示；或提供「保留這台位置／前往帳號位置」。後者會改變現行同步規格，須明確記錄決定。
- 若提供選擇，建議未選擇前保留目前畫面及本機位置，暫停衝突進度的自動覆寫；離開後再次進入時如何處理待決狀態也須確認。

## 驗收條件

- [ ] 上述政策已確認並同步記錄；不將不同的衝突策略混用在登入合併與閱讀中同步而未說明。
- [ ] 只有伺服器確認相應版本已寫入才顯示「已同步」；有較新的本機進度待送出時仍顯示待同步。
- [ ] 訪客顯示本機保存語義；會員斷線、請求失敗或 session 過期時，不錯誤顯示雲端保存成功。
- [ ] 可重試失敗同步；同一作品寫入按序處理，較舊回應不覆蓋較新狀態，避免並行 flush 製造自身衝突。
- [ ] 若採用選擇方案，顯示雙方章節／段落供判斷；保留本機位置時以最新版本條件再提交，二次衝突仍需處理，不能無條件覆寫。
- [ ] 若採用伺服器優先方案，跳轉前後的提示清楚可辨識，且同步錯誤不刪除本機位置。
- [ ] 驗證兩台裝置同書不同章、同章不同段、離線回線、連續切章與離開閱讀器；完成的舊請求不影響已離開的作品。

## 不在範圍

用「閱讀最遠」自動選擇勝方、按頁碼同步，以及重建整套會員狀態系統。

## 依賴

沒有其他 ticket 的硬性依賴；衝突策略確認是實作前置條件。
