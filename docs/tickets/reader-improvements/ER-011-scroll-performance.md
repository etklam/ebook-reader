# ER-011｜降低長章節捲動的錨點計算成本

- 優先級：P1
- 工作量：中
- 類型：AFK
- 狀態：implemented（實作及自動驗證完成；真機 L3 仍待驗）

## 要做的事

身為閱讀長章節的手機讀者，我希望捲動流暢，同時準確保存正在閱讀的位置。

目前每次捲動事件先擷取錨點，再延後保存；擷取會從章首逐段查詢 DOM 位置。因此延後的是寫入，不是段落計算。先建立可重現的長章節基線，再減少重複掃描，例如合併捲動工作、由上一個段落附近查找，或追蹤可見候選段落。選擇以量測結果為依據。

## 驗收條件

- [x] 記錄普通章與長章的裝置／瀏覽器、段數、字數、圖片、閱讀模式與操作序列，取得修改前的 trace。
- [x] 在相同資料與操作下比較錨點擷取次數、段落幾何查詢次數、耗時 p50／p95、長任務與捲動幀表現；原始或摘要證據可重跑。
- [x] 一般連續捲動不再於每個事件從章首掃到目前段落；章尾操作的計算量減少，且沒有把相同成本移到每幀執行。
- [x] 需要立即保存、切章、切模式或離開頁面時仍擷取最新錨點；快速跳到章首／章尾也準確。
- [x] 字號、行距、繁簡、轉屏與圖片載入改變排版後，候選或位置快取正確失效，回錨仍落在同一 canonical 段落。
- [x] 涵蓋長段落、含圖片章節、快速滑動與分頁往返；正常短章的開章／互動沒有實質回歸。
- [x] 真機結果與桌面模擬分開記錄；未取得改善證據時如實報告，不能以程式碼較短或加上節流即宣稱變快。

## 不在範圍

重寫閱讀引擎、整本 DOM 虛擬化、更動 canonical 位置契約，以及全面替換排版方式。
