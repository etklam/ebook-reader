# RV-015｜劃線、筆記標籤與筆記匯出

- 嚴重度：不適用（功能需求）
- 優先級：P2
- 工作量：大
- 類型：HITL（需決定劃線在繁簡檢視下的定位語義）
- 狀態：open

## 要做的事

讓讀者在正文上劃線、替劃線與書籤加標籤分類、在全書或整個書架中搜尋自己的筆記，並把筆記打包匯出成 TXT／HTML。

## 分析

### 現狀

有的是**段落級**書籤：`bookmarks` 表（`schema.ts:486`）記 `workId`／`chapterId`／`revisionId`／`paragraphIndex`／`note`，`revisionId` 在建立時凍結、永不因為 head 或 release 移動而改寫（§35）。ER-003 已交付備註的新增／編輯／按作品篩選，`GET /api/me/bookmarks` 支援 workId 篩選與分頁。

沒有的是：字元範圍的劃線、標籤、筆記匯出、跨書筆記搜尋。

選取文字的基礎設施其實已經在：`ReaderPage.tsx:210-221` 掛了 `selectionchange` 並記住目前選取（錯字回報用）。

### 核心難題：劃線要存什麼

段落級書籤只需要一個整數，所以它對重排、字型變更、繁簡轉換全部免疫。劃線需要「段落內的第幾個字到第幾個字」，而這個數字會被兩件事動搖：

**(a) 繁簡轉換。** `conversion.ts` 是 view-time 的純字串映射，段數不變 —— 但**字元數不保證不變**。opencc 的繁↔簡不是嚴格一對一：簡體「发」對應繁體「發」或「髮」，而繁→簡方向是多對一。多數情況長度相同，但不能當作契約。如果劃線的偏移是在簡體檢視下擷取、而還原時用繁體原文，位置就會漂。

這是本票唯一真正需要決策的點，兩條路：

- **A（建議）**：劃線的偏移**一律以 canonical 原文為準**。讀者在轉換後的檢視中選取時，把選取映射回原文偏移再儲存；還原時把原文偏移映射到目前檢視。需要 `convertParagraphs` 額外產出一個字元對照表，而這是 opencc 不直接提供的 —— 要逐字轉換並累積長度差，成本是一次 O(段長)，可接受。
- **B**：連同擷取時的 `conversion` 模式一起存，還原時只在同一模式下精確、其他模式退化為「標示整段」。實作便宜很多，但同一條劃線在切換繁簡後會變成另一個東西，讀者會覺得壞了。

**(b) 修訂。** `revisionId` 凍結解決了這一半：劃線綁在當時那個 revision 的正文上。但章節改版後，讀者在新版看到的是什麼？書籤的做法是保留錨點不動；劃線因為是字元範圍，落在改動過的句子上就會指向不同的字。需要定義：改版後劃線是標示為「原文已變」而保留，還是嘗試重新定位。**不要自動重新定位** —— 猜錯比誠實說「這段改過了」差得多。

### 其餘三項

**標籤。** 新一張 `note_tags`（或在筆記列上一個受限的 `text[]`）。要決定標籤是每人全站共用一組還是每部作品一組。上限必要：每條筆記幾個、每個標籤多長、每人總共幾個標籤。

**跨書搜尋筆記。** `GET /api/me/bookmarks` 已有 workId 篩選與分頁，加 `q` 搜尋 `note` 文字與標籤是小改動。要注意與 RV-001 相同的可見性規則：`me.ts:88` 對 `removed` 作品回 `null`，搜尋結果不能把已刪除作品的筆記連同書名洩漏回來。

**匯出。** 與 `export/formatters.ts` 無關 —— 那是整本書的伺服器端匯出，本票是個人筆記。TXT 與 HTML 兩種格式，應在**伺服器端**產生並附正確的 `Content-Disposition`（檔名要走既有 `filenamePart` 的處理）。HTML 必須轉義筆記內文：那是讀者自己輸入的文字，但匯出檔可能被任何東西開啟。原始需求中的「直接寄到電子信箱」在 web 上沒有等價物，除非加一條伺服器寄信管道；`mailto:` 帶不動附件。建議第一版只做下載，並在票內說明。

## 驗收條件

- [ ] 劃線的偏移語義已決策（A 或 B）並記錄理由；若選 A，有測試證明在繁／簡／原文三種檢視間切換時劃線位置不漂。
- [ ] 劃線不改變段落數與 `paragraph_index`，不干擾既有書籤、進度、朗讀與錯字回報的定位。
- [ ] `[[img:…]]`／`[[note:…]]` 段落不可劃線，與 `conversion.ts:20-26` 同一理由。
- [ ] 劃線綁定建立當時的 `revisionId`；章節改版後明確標示「原文已變」，不自動重新定位。
- [ ] 標籤有數量與長度上限；超限給明確錯誤而非靜默截斷。
- [ ] 可在單本或全部筆記中以關鍵字搜尋筆記內文與標籤；已刪除或草稿作品的筆記不洩漏作品資訊。
- [ ] 可匯出 TXT 與 HTML；HTML 的筆記內文經過轉義；檔名走既有的 `filenamePart` 處理。
- [ ] 未登入與非擁有者不能讀寫任何劃線、標籤或匯出。
- [ ] 一章內大量劃線（例如 200 條）時，換章與捲動無可觀察退化。
- [ ] `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm --filter server test:e2e`、`pnpm --filter web test:browser`、`pnpm db:verify` 通過。

## 不在範圍

伺服器寄信（「發送到電子信箱」）、劃線顏色以外的樣式自訂、匯出時套用繁簡轉換或 RV-013 的人名替換（匯出應為 canonical 原文）、與第三方筆記服務同步。

## 依賴

與 RV-013（人名替換）共用同一個「顯示文字 ≠ canonical 文字」的問題，兩票的偏移映射應該用同一套工具，建議同一輪處理。
