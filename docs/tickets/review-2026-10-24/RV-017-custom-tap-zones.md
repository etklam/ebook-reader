# RV-017｜可自訂的觸控區域

- 嚴重度：不適用（功能需求）
- 優先級：P3
- 工作量：中
- 類型：HITL（需決定可綁定的動作清單）
- 狀態：open

## 要做的事

把閱讀器現有的三條水平觸控帶換成可自訂的格狀區域（例如九宮格），每一格可綁一個動作。

## 分析

### 現狀

`pagination.ts:23` 的 `tapZone(y, height)` 只看**垂直**位置，回傳 `'prev' | 'next' | 'chrome'`：上 25% 上一頁、下 25% 下一頁、中間一半呼出介面。`TAP_BAND = 0.25`。

兩個既有規則本票不能破壞：

1. **只在分頁模式生效。** `ReaderPage.tsx:630` 是 `if (settings.mode === 'paginated')`；捲動模式下點擊一律只切換介面，因為捲動模式裡「點一下翻頁」與捲動本身語義衝突。自訂區域若要在捲動模式也生效，必須是明確的另一個決定，不是順手擴充。
2. **量不到高度就當作呼出介面。** `tapZone` 的註釋寫得很清楚：尚未排版完成的章節第一次點擊會量到零高度，而此時「翻頁會移動已儲存的位置，呼出介面不會」—— 所以寧可呼出介面。任何新的區域解析函式都要保留這個保守的預設。

另有兩道保護在 `ReaderPage.tsx:627-628`：有文字選取時不處理點擊、點在 `a` 或 `button` 上不處理。滑動翻頁（`onPointerDown`/`onPointerUp`，`SWIPE_MIN`、700ms 的 flick 判定）與點擊共存，`swipeHandled` 用來吞掉滑動尾端產生的合成 click。區域變多之後這幾條更重要，不是更不重要。

### 設計要點

**格狀解析應該是純函式。** 現有的 `tapZone` 刻意放在 `pagination.ts`（檔頭：「DOM logic lives in position.ts/components; these stay testable without a browser」）。新的 `zoneAt(x, y, width, height, layout)` 應該在同一個檔案、同樣可在 node 測試，所有邊界條件（零尺寸、剛好落在格線上、單格佔滿）都用表格測試覆蓋。

**動作清單要先定。** 閱讀器現成可綁的動作：上／下一頁、上／下一章、切換介面、開目錄、開設定、開搜尋、建立書籤（`createBookmark` 已在 `ReaderPage` 匯入）、開始／停止朗讀、回作品頁。原始需求提到的「調亮度」在 web 上做不到（瀏覽器不能改系統亮度），若要做只能是 RV-016 的濾鏡強度 —— 這是不同的東西，UI 不應叫它「亮度」。

**格數。** 原始需求提到多達 24 個區域。3×3 已經接近手指在手機上能可靠命中的極限（390px 寬的三分之一是 130px，合理；但 4×6 的一格只有 97×140，且沒有視覺邊界可瞄準）。建議提供 2×2／3×3／1×3（維持現狀）三種版面，上限到 3×3，並在票內記錄為何不做 24 格。若維護者堅持更密的格線，必須同時提供一個「顯示區域提示」的覆蓋層，否則讀者無從得知自己點了哪一格。

**可發現性與可回復。** 自訂之後，一個新裝置上的讀者不知道哪裡點了會怎樣。需要一個設定內的互動預覽（點一下該格就說出它會做什麼，而不是真的執行），以及一鍵回復預設。

**無障礙。** 觸控區域不是可聚焦元素，鍵盤與螢幕閱讀器使用者完全碰不到。現有的鍵盤路徑（`use-reader-keyboard.ts`）必須保持獨立且完整 —— 區域自訂不能成為某個動作的唯一入口。

### 設定儲存

每部作品一組還是全站一組？建議全站一組（手勢是肌肉記憶，不應隨書改變）。存進 `ReaderSettings` 以沿用既有的帳號偏好同步；但這是一個結構化物件而非純量，`normalizeSettings` 需要對它做形狀驗證與上限檢查，不能信任伺服器或 localStorage 回來的任意 JSON。

## 驗收條件

- [ ] 區域解析是純函式、在 node 可測；零尺寸、格線邊界、單格佔滿等邊界條件有表格測試。
- [ ] 量不到尺寸時仍退回「呼出介面」，永不盲目翻頁；有測試。
- [ ] 文字選取中與點在互動元素上時不觸發任何區域動作；滑動翻頁與點擊不互相誤觸發。
- [ ] 可綁定的動作清單已決定並記錄；「調亮度」若保留，名稱如實反映它是濾鏡強度而非系統亮度。
- [ ] 版面選項不超過 3×3，或若超過則同時提供區域提示覆蓋層；不做 24 格的理由記錄在票內。
- [ ] 設定面板有互動預覽（點該格說明其動作，不執行）與一鍵回復預設。
- [ ] 鍵盤路徑維持完整，任何動作都不是只能靠觸控區域達成。
- [ ] 設定的形狀與上限在 `normalizeSettings` 驗證，損壞或超限的資料退回預設而非崩潰；有測試。
- [ ] 捲動模式是否啟用區域已明確決定並記錄。
- [ ] `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm --filter web test:browser` 通過。

## 不在範圍

手勢（雙指、長按、雙擊）的自訂 —— 與現有的選取、滑動、長按選字互動面大得多，另開票；實體按鍵自訂（見 README 的暫緩項）。

## 依賴

RV-016 相關：若「調亮度」要綁成一個動作，它實際調整的是 RV-016 的濾鏡強度。
