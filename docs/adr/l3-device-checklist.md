## 0｜啟動（每次測試前）

```bash
pnpm db:up                 # PostgreSQL 18
pnpm db:migrate            # migration + grants（跑兩次無害）
pnpm dev:api               # :3000
pnpm dev:worker            # 匯入 worker
pnpm dev:lan               # vite --host，手機可連（預設 pnpm dev:web 只綁 loopback）
pnpm seed:l3               # 建三部已發布樣本作品（可重跑，不會重複建）
```

`pnpm dev:lan` 會印出 `Network: http://<lan-ip>:5173/`，**該 IP 就是手機要開的網址**。

### 必做設定：CSRF 允許 LAN origin

vite 的 proxy 會改寫 `Host`，所以 API 無法用 host 比對 origin，dev 一律依賴
`CSRF_ALLOWED_ORIGINS`。**沒加 LAN origin 的話手機上每一個 POST 都會 403
`origin_mismatch`**（登入、收藏、書籤、進度同步全部失敗）。在 `server/.env`：

```
CSRF_ALLOWED_ORIGINS=http://localhost:5173,http://<lan-ip>:5173
```

改完重啟 `pnpm dev:api`。驗證（在電腦上）：

```bash
curl -s -X POST "http://<lan-ip>:5173/api/auth/login" \
  -H 'content-type: application/json' -H 'Origin: http://<lan-ip>:5173' \
  -d '{"email":"l3-seed@example.test","password":"l3-seed-password"}'
# 期望 {"ok":true}；若見 {"error":"origin_mismatch"} 就是上面這步沒做
```

### 手機與網路

- 手機與電腦必須在同一個 Wi-Fi；公司／公共網路常見 client isolation，連不上就改用手機熱點
- macOS 防火牆若擋 node，允許連入連線
- **注意：API 預設綁 `0.0.0.0`，所以 `:3000` 在 LAN 上也直接可達。** 這是 dev 行為；
  正式部署在 proxy 後面要設 `BIND_HOST=127.0.0.1`
